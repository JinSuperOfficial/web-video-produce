## Core Philosophy

Videos aren't "cut" together, they're **computed by code**. That's why it's naturally suited for LLMs:

1. **The timeline is the single source of truth** — video length is determined by the voiceover. The order is always: script → voiceover → get frame numbers for each line → then write visual code.
2. **Every frame is a pure function f(frame)** — `Math.random()`, `Date.now()`, and accumulating time via `requestAnimationFrame` are forbidden. Rendering must be reproducible.
3. **Sample first, full render later** — render 1 still frame to confirm fonts/composition, then 3 seconds, and only then render the full video.
4. **Leave audio to professional tools** — don't write code to synthesize TTS, don't write code to mix audio. edge-tts makes sound, FFmpeg finishes.
5. **Delivery means verification** — after rendering, use `ffprobe` to report specs, extract frames to inspect visuals, then hand it to the user.

## Two Capabilities

| Capability | Input | What it does | Output |
| --- | --- | --- | --- |
| **Generate** | A piece of copy / a topic | Segment → voiceover+subtitle timeline → write visual code → frame-by-frame render → compose | `output/final.mp4` |
| **Edit** | Existing assets (yours/someone else's) | EDL declarative timeline → conform normalization → trim/transitions/watermark/aspect/compress | `output/edit.mp4` |

The two routes can be mixed: animated clips generated by Remotion can be written into the editing timeline like ordinary assets.

## Quick Start

**macOS / Linux (Bash, also works in Windows Git Bash / WSL)**

```bash
git clone https://github.com/JinSuperOfficial/web-video-produce.git
cd web-video-produce

# 1) Run self-check: environment / project validation / output specs
python3 scripts/wvp.py doctor

# 2) Dependencies
npm install                     # or other
npx remotion browser ensure     # download Chrome Headless Shell
python3 -m venv .venv && .venv/bin/pip install edge-tts
# Activate venv, install dependencies (Edge-TTS)

# 3) Render: voiceover → timeline check → static check → render → mux audio → verify
python3 scripts/wvp.py render --out output/intro10s.mp4
#    Render a 2s half-resolution sample first to save time: --scale 0.5 --frames 0-60
#    Reuse existing voiceover: --no-tts

# 4) Check timeline: segment/frame/word alignment (--verify-audio decodes the audio track)
python3 scripts/wvp.py timeline --words
python3 scripts/wvp.py timeline --verify-audio

# 5) Editing route: check commands first, then run
python3 scripts/vedit.py transitions                        # when unsure which transition to use
python3 scripts/vedit.py plan  --edl examples/edit-plan.example.json
python3 scripts/vedit.py build --edl examples/edit-plan.example.json
```

## Workflow

![pipeline](docs/images/pipeline.jpg)

```
Text → segmented script (JSON) → edge-tts voiceover + subtitles + frame-number timeline + per-word timestamps
                              ↓
            Remotion / React / Three.js / Canvas for visuals
         (motion library + transitions layer + SFX track)
                              ↓
                  frame render → FFmpeg compose → MP4
```

The voiceover step produces four things, and they are the anchors for everything:

| Artifact | Purpose |
| --- | --- |
| `vo.mp3` | Full voiceover track (including inter-segment pauses and background music) |
| `vo.srt` / `vo.vtt` | Subtitles strictly aligned to the audio track (split by punctuation, tightly following real speech) |
| `manifest.json` | **Start/end frame numbers for each line** — visual code only trusts this, not "about a few seconds" |
| `words.json` | **Per-word timestamps** — karaoke highlight, SFX sync, per-word proofreading |

## TTS: edge-tts by default, or use your own

![voice](docs/images/voice.jpg)

### Default: edge-tts (free, works out of the box)

```bash
# List all Chinese voices
.venv/bin/python scripts/tts_edge.py --list-voices zh

# Voice selection: audition multiple voices for the same sentence, don't pick blindly
.venv/bin/python scripts/tts_audition.py --outdir output/voice_samples --rate +5%

# Formal generation (default whole-segment prosody mode + auto BGM + inter-segment pauses)
.venv/bin/python scripts/tts_edge.py \
  --script examples/script.intro10s.json \
  --outdir public/voice \
  --voice zh-CN-XiaoxiaoNeural --rate +5% --fps 30 --normalize
```

| Voice | Character | Scenario |
| --- | --- | --- |
| `zh-CN-XiaoxiaoNeural` | Female · warm, general | Narration, storytelling (default) |
| `zh-CN-YunxiNeural` | Male · sunny, youthful | Tech, Vlog |
| `zh-CN-YunjianNeural` | Male · deep, powerful | Promos, trailers |
| `zh-CN-YunyangNeural` | Male · professional broadcast | News, documentaries |
| `zh-CN-XiaoyiNeural` | Female · lively, bright | Short videos, tutorials |

### Three hard constraints (pitfalls we hit, now baked into the code)

| Constraint | Reason | Measured |
| --- | --- | --- |
| **Don't use periods「。」in the script** | Periods trigger "falling intonation + long pause" at sentence end; one falling tone per sentence = robot reading a textbook. The tool **auto-removes** them and tells you how many it removed in the log | — |
| **Whole-segment prosody mode** (default) | Segment-by-segment synthesis **adds about 0.6s of trailing silence per request**, and intonation resets at each segment start, making it sound choppy | Same script: segmented 8.75s → whole-segment 6.98s; the 1.8s difference is **all fake pauses** |
| **Speech rate +0% ~ +5%** | Above +10% it sounds floaty and sibilant | — |

Pauses and BGM are on by default: **400ms real pause between segments** (not seamless), **600ms breathing room at the end**, **BGM sidechain ducking** (music automatically lowers when speaking).

> The background music is synthesized in code by `scripts/make_bgm.py` (sine additive synthesis + chord crossfade), **royalty-free, free for commercial use, seamlessly loopable**. To swap it, just drop an mp3 into `assets/bgm.mp3`.
>
> Mixing uses **multi-band carve** instead of overall ducking: first Linkwitz-Riley crossover (300Hz / 3400Hz), then sidechain compression only on the vocal band.
> Measured low-frequency energy on the same video — untreated −35.4dB / overall ducking −43.2dB (music deflated) / carve −36.1dB (**music preserved**).
> Loudness uses two passes of `loudnorm` (linear gain), `--loudness-target social|podcast|broadcast` = −14 / −16 / −23 LUFS.

### Plug in your own TTS API

As long as your service can "take text, return audio", it can be plugged in — the timing and subtitle logic for speech synthesis is fully reused.

**A. OpenAI-compatible `/audio/speech`** (OpenAI, SiliconFlow, Zhipu, Volcano Ark and most vendors use this shape)
(Local ones haven't been tested, but they probably work too.)

```bash
export TTS_API_KEY=sk-xxxx        # or --tts-api-key

.venv/bin/python scripts/tts_edge.py --script examples/script.intro10s.json \
  --outdir public/voice \
  --engine openai \
  --tts-base-url https://api.openai.com/v1 \
  --tts-model gpt-4o-mini-tts \
  --voice alloy \
  --bgm assets/bgm.mp3
```

**B. VoiceCraft-style API** (`POST /v1/audio/speech`, fields `input` / `voice` / `speed` / `pitch` / `style` / `volume`)

This comes from the open-source project [JinSuperOfficial/tts-voice-magic](https://github.com/JinSuperOfficial/tts-voice-magic).
The original TTS project author is upstream in that TTS repo (VoiceCraft, based on Microsoft Edge TTS, one-click deploy to Cloudflare Workers). It adds a `style` emotion/character parameter over A (`general` / `newscast` / `cheerful` / `serious` / `gentle` …).

```bash
# Deploy your own (recommended): https://github.com/JinSuperOfficial/tts-voice-magic
# Or use an already deployed instance (tested locally)
.venv/bin/python scripts/tts_edge.py --script examples/script.intro10s.json \
  --outdir public/voice --fps 30 \
  --engine voicecraft \
  --tts-base-url https://tts.jinsuper.cn/v1 \
  --voice zh-CN-XiaoxiaoNeural \
  --rate +5% --tts-style newscast
```

> [!WARNING]
> A pitfall we hit in testing: Cloudflare-fronted sites block Python's default User-Agent
> (`Python-urllib/3.x` → `HTTP 403 error code: 1010`), while `curl` works.
> The script already sends a normal UA by default, so it works out of the box; if you switch to another HTTP client, set the UA yourself.

**C. Fully custom endpoint** (use a JSON template when each vendor has different fields)

```bash
.venv/bin/python scripts/tts_edge.py --script script.json --outdir public/voice \
  --engine custom \
  --tts-endpoint https://your-tts.example.com/v1/synthesize \
  --tts-header "X-App-Id=my-app" \
  --tts-payload '{"text":"{text}","speaker":"{voice}","format":"mp3"}' \
  --voice my-speaker-id
```

Available placeholders in the template: `{text}` `{voice}` `{model}` `{speed}`; the response body can be raw audio bytes.

> Self-hosted engines can't provide per-word boundaries, so it automatically switches to segmented mode (one request per segment) — the timeline is read back via `ffprobe` and remains precise;
> subtitles are generated "one sentence per segment", and `words.json` honestly marks `precision: "none"` instead of pretending to have per-word precision.

## Editing Mode (EDL-driven)

> [!NOTE]
> Experimental

![editing](docs/images/editing.jpg)

Describe the timeline in JSON; the tool generates and runs FFmpeg commands. **Three-stage pipeline**, never feed heterogeneous assets directly into the filter graph:

```
Asset (heterogeneous) ──conform──▶ unified spec ──assemble──▶ timeline ──finish──▶ output/edit.mp4
  different resolution/fps/audio      trim+xfade+acrossfade      overlay/mix/subtitle/compress
```

```bash
# Check commands first, then act (editing is irreversible, don't run blindly)
python3 scripts/vedit.py plan  --edl examples/edit-plan.example.json
python3 scripts/vedit.py build --edl examples/edit-plan.example.json

# Landscape → portrait (blurred background, common for short videos)
python3 scripts/vedit.py build --edl examples/edit-plan.example.json --aspect vertical
```

Capabilities: trim / multi-segment concat / **xfade transitions** (58 types, paired with audio acrossfade) / watermark and picture-in-picture / three aspect adaptations (pad·crop·blur) / target-size compression / mix with Remotion-generated clips into a final video.

Four hard constraints:

1. **Conform before concat** — unify resolution/fps/codec/sample rate/audio track count; auto-add silence if no audio track;
2. **offset = accumulated duration of previous segments − transition duration**, and `transition duration ≤ min(prev, next)/2`; out-of-bounds throws an error directly;
3. **Pair audio and video processing** — if there's an xfade, there must be an acrossfade with the same value, eliminating pops and cut-offs;
4. **Four-level fallback** — `xfade → concat filter → concat demuxer(copy) → error and preserve the scene`; it will clearly tell you if it fell back.

## Validate Before Rendering

```bash
python3 scripts/validate.py                      # Source + timeline: results in under 1 second
python3 scripts/validate.py --out output/final.mp4   # Plus output specs, color space, loudness
python3 scripts/validate.py --json               # Agent-friendly
```

It checks: determinism rules (`Math.random`/`Date.now`/self-running animations), `manifest.json ↔ config.ts` fps and duration consistency,
whether all scene ids are in the voiceover script, whether assets referenced by `staticFile` and EDL exist, whether Chinese fonts are loaded,
output pixel format / **color space bt709** / color range tv / peak / average volume / overall LUFS.

> This validator caught a real issue: Remotion doesn't pass color parameters by default, so the output was written as full-range `yuvj420p` + BT.601,
> and colors would shift when platforms transcode. Now `remotion.config.ts` pins `Config.setColorSpace('bt709')`.

## FAQ

<details>
<summary><b>Chinese renders as tofu blocks □□□</b></summary>

Headless environments often have no CJK font at all. `SKILL.md` §4.5 gives three solutions; the recommended one is to put woff2 into `public/fonts/` and load via `@remotion/fonts` (one file, one request, fully offline).
</details>

<details>
<summary><b>Rendering is slow</b></summary>

By default `@remotion/google-fonts` preloads all font subsets on first render (about 294 requests, 1-2 minutes). Switching to bundled font files greatly speeds this up. Also render a sample with `--scale=0.5` first, then render the full video once confirmed.
</details>

<details>
<summary><b>Voiceover sounds fake</b></summary>

See [Three hard constraints](#three-hard-constraints-pitfalls-we-hit-now-baked-into-the-code) above. The tool already does this by default: remove periods, whole-segment prosody, slower rate, add pauses, add BGM. If still unsatisfied, switch engines (Azure SSML / MiniMax / Volcano / local GPT-SoVITS clone).
</details>

<details>
<summary><b>Corrupted frames after concat / black frames at transitions / audio pops</b></summary>

Inconsistent asset parameters. `vedit.py` enforces conform first; when manually concatenating, be sure to unify resolution, fps, pixel format, sample rate, and **if there's an xfade, there must be an acrossfade**.
</details>
